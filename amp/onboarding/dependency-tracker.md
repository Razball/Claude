# Onboarding Dependency Tracker

Every part of the product that requires client input to work. If these compound without resolution, new clients don't see value until week 3 — churn trigger.

| Dependency | What breaks without it | When to collect | Owner |
|---|---|---|---|
| Revenue and margin data | Unit economics, CAC targets, pricing recommendations | Day 1 | Client |
| Team structure and roles | Routing, approvals, communication | Day 1 | Client |
| Top 3 problems owner spends time on | Automation priority queue | Day 1 | Client |
| Tool stack | Tool resolution protocol (P7) | Day 1 | Client |
| Current ad / acquisition data | Proactive recommendations | Week 1 | Client |
| Process documentation | Layer 2 workflows | Week 1–2 | Client |
| Brand voice samples (3) | Prompt elevation tone | Session 2 | Client |
| Credentials for tool access | Agent deployment | Week 2 | Jackson (coordinate) |

## Rules
- New dependency identified in a session → add here immediately.
- If a dependency can't be collected in Sprint, add it to the Client Module with explicit "inference" flag until confirmed.
- If the same dependency blocks 2+ clients, it belongs in the standard Sprint scope.
